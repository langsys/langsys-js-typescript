# GitHub CLI Setup for Release Automation

## Installation

### macOS (Homebrew)

```bash
brew install gh
```

### macOS (MacPorts)

```bash
sudo port install gh
```

### Other platforms

See [cli.github.com/manual/installation](https://cli.github.com/manual/installation).

## Authentication

### Interactive (recommended)

```bash
gh auth login
```

Prompts for:
1. GitHub.com vs GitHub Enterprise
2. Auth method (browser or token)
3. Browser flow opens GitHub to authorize the CLI; token flow expects you to paste a PAT.

### Personal Access Token

1. Generate at [github.com/settings/tokens/new](https://github.com/settings/tokens/new).
2. Required scopes:
    - `repo` (full repo control)
    - `workflow` (update Actions workflows)
    - `write:packages` (publish to GitHub Package Registry, if you ever use it)
3. Authenticate:
    ```bash
    gh auth login --with-token < token.txt
    ```

### Check status

```bash
gh auth status
```

## How `publish.sh` uses `gh`

The release script invokes:

1. **Auth check** — `gh auth status`
2. **Release creation** —
    ```bash
    gh release create vx.y.z \
        --title "vx.y.z" \
        --notes "<auto-generated from commit history>"
    ```

That's it. Everything else (commits, tags, push) goes through plain `git`, and the package upload goes through `npm publish`.

## Security notes

- Credentials live in your system keychain — never in the repo.
- Auth persists across terminal sessions.
- Revoke from GitHub settings any time.

## Alternative: environment variables (no `gh`)

If you'd rather not install `gh`, set:

```bash
export GITHUB_TOKEN="your-personal-access-token"
```

…and use `curl` to create releases:

```bash
curl -X POST \
    -H "Authorization: token $GITHUB_TOKEN" \
    -H "Accept: application/vnd.github.v3+json" \
    https://api.github.com/repos/langsys/langsys-js-typescript/releases \
    -d '{"tag_name":"v1.2.3","name":"v1.2.3","body":"Release notes here"}'
```

`gh` is recommended because it's more ergonomic and keychain-backed.
